## Build settings and tool provenance

- build.options.json and compile_commands.json identify ESP32 Dev Module, base FQBN esp32:esp32:esp32, ARDUINO_ESP32_DEV and board variant esp32. Settings include upload speed 921600, CPU 240 MHz, flash 80 MHz / 4 MB, default partitions, PSRAM off, and Arduino loop/events on core 1. The compiler optimization setting is -Os, and the Arduino ESP32 hardware and esp32-libs packages are both version 3.3.7.
- compile_commands.json identifies the esp-x32/2511 Xtensa GCC executable. Its version and the linked ELF's .comment show GCC 14.2.0, crosstool-NG esp-14.2.0_20251107. The ELF also carries comments for GCC 11.2.0 and 4.8.5 from linked components. Use the compiler command for the sketch's toolchain identity.
- The application descriptor in the binary reports IDF v5.5.2-729-g87912cd291 and project arduino-lib-builder. The descriptor's February 11, 2026 date is an embedded library-build value. The cache metadata supplies the observed March 26 artifact dates.
- Preserve the terms independently: build.options.json declares FlashMode=qio. The generated flash_args explicitly says --flash-mode dio, and byte 2 of the application and bootloader image headers is 02 (DIO). The merged image's bootloader header at 0x1000 also has 02. This establishes the recorded configuration versus packaged-image modes.
- compile_commands.json, libraries.cache and dependency .d files agree on the library paths in [project-drive]/Desktop/Waveshare 2.8 GUI/Arduino/Sketchbook/libraries. The matching local library.properties files declare EspSoftwareSerial 8.1.0 (file timestamp March 22) and Adafruit NeoPixel 1.15.4 (file timestamp March 23). Their paths are historical cache evidence. The version files are local corroboration and are not version strings embedded in the historical dependency lists.

## Historical upload evidence recovered from Arduino IDE logs

The cache-only uncertainty about whether the IDE uploaded v1.13 is superseded by the March 26 IDE event log. Original logs are under [local-user]/AppData/Roaming/Arduino IDE/. The March 26 log identifies Arduino IDE 2.3.8 at line 21 and Arduino CLI 1.4.1 at lines 19073–19074.

- The final exact-cache build event occurs March 26 at 19:49:09.550. Line 18691 names cache C141CC7675380B4A2DD7B7286356D2EE. At 19:49:16.979, line 19069 records the IDE's post-upload result for powderbot_personality_v1_13 on COM6, with the same base ESP32 Dev Module FQBN and settings as the cache. At lines 19103–19105, the IDE successfully reopens the COM6 serial monitor at 115200.
- The locally installed IDE 2.3.8 backend bundle at C:/Program Files/Arduino IDE/resources/app/lib/backend/main.js emits “Received port after upload” inside doUpload when it receives a CLI UploadResponse with getResult() and getUpdatedUploadPort(). Upload errors use a separate stream error branch. The nearby EOF and access-denied lines are marked serial-monitor cleanup following CLOSE/QUIT. The scoped sequence contains no upload error. This supports completed host uploads. The log does not preserve byte-level flash verification text or application boot output.
- The COM6 entry reports USB VID 0x1A86, PID 0x7523 and a blank USB serial-number field. Port, board profile, sketch and time are established. They do not uniquely identify the physical board. Later logs record other firmware uploaded on COM6, and there is no evidence here of what is on a device today.
